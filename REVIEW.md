# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It treats the punch-in's existing clock/date as shift-local time and cannot anchor an overnight punch to the attendance day. | A UTC instant for 09:40 IST can be judged against 09:30 UTC; an early-morning overnight punch uses the wrong shift start. | Convert instants to IST, anchor to the attendance date, and apply the strict 10-minute grace in whole seconds. |
| 2 | `compute_work_hours` | Built-in `round()` uses half-even behavior and calculations can include fractions of a second. | A 450-second duration is 0.125 hours and must report 0.13, not 0.12. | Truncate to whole seconds and quantize `Decimal` with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | It always places shift end on the attendance date, can mix naive and aware datetimes, and counts overtime below 30 minutes. | A 22:00-06:00 shift ending at 06:40 should count 40 minutes; a 20-minute overrun should count zero. | Build the end instant in IST on the correct day and apply the 30-minute threshold after flooring. |
| 4 | `/health` | It returns `ok` without contacting MongoDB. | Stop MongoDB and request `/health`; the starter still reports ready. | Ping MongoDB and return 503 on connection failure. |
| 5 | `create_employee` | A read-before-insert duplicate check races under concurrent requests and there is no unique database guarantee. | Send parallel creates with one `emp_code`; more than one can pass the check. | Create a unique `emp_code` index and translate `DuplicateKeyError` to 409. |
| 6 | `create_employee` | `created_at` is a naive local datetime and the response exposes a datetime string instead of epoch milliseconds. | Inspect a created employee response and compare it with the contract's integer instant format. | Store UTC BSON datetime and serialize API instants as epoch milliseconds. |
| 7 | `list_employees` | Page 1 skips a full page, `total` ignores the department filter, and results are not sorted by `emp_code`. | With 25 employees, page 1 starts at item 21; a department filter still reports the whole collection count. | Use `(page - 1) * page_size`, count with the same filter, and sort in MongoDB. |
| 8 | `EmployeeIn` | Employee code, email, field lengths, date format, and unequal shift times are not validated. | Submit a malformed code/email, invalid date, or identical shift boundaries. | Add schema constraints and date/shift validators. |
| 9 | `punch_in` | An unknown employee is dereferenced and becomes a 500 instead of 404. | Punch in with an unseeded `emp_code`. | Check employee existence before using shift fields. |
| 10 | `punch_in` | `fromtimestamp()` uses the host timezone, truthiness treats zero as an omitted timestamp, and the stored instant is not explicitly truncated. | Run under a non-UTC host timezone or submit a seconds-looking/fractional timestamp. | Strictly validate epoch milliseconds, convert in UTC, truncate to seconds, then derive the IST date. |
| 11 | `punch_in` | Check-then-insert is not concurrency-safe; it also misses overnight attendance-day rules and accepts arbitrary statuses. | Parallel punches can both pass the read; use an early-morning overnight punch or `ABSENT` status. | Use the unique `(emp_code, date)` index with insert-only conflict handling, calculate R1 dates, and restrict status to presence values. |
| 12 | `list_attendance` | It loads every matching record into Python and sorts/slices in memory, which does not scale to 100,000 records. | Measure memory/query time on a large collection. | Count and page with MongoDB filters, sort, skip, and limit, backed by indexes. |
| 13 | `list_attendance` | Same-date records have no `emp_code` tie-break; returned records include an `id` and serialize punch/history instants as ISO strings. | Request multiple employees on the same date and inspect response fields/types. | Sort by date descending then code ascending; serialize only contract fields and recursively convert instants to milliseconds. |
| 14 | `list_attendance` | Page bounds and `date_from <= date_to` are not validated. | Send page 0, page size 101, or a reversed date range. | Add query constraints and reject reversed ranges with 422. |
| 15 | MongoDB setup | No startup indexes are created for uniqueness, lookups, or the required sorts. | Inspect indexes on a freshly seeded database or run explain. | Create idempotent unique and query-supporting indexes in the app lifespan. |
| 16 | `list_employees`, `attendance_filter` | A supplied empty optional string is treated as omitted, so the exact-match filter is skipped. | `GET /employees?department=` returns all employees; `GET /attendance?emp_code=` returns all records. | Apply optional filters when the value is not `None`, preserving exact-match semantics. |

Not defects: punch-out, regularization, analytics, and explain routes are marked as Part B work in the brief, so their absence from the Part A starter is intentional. `_id` is intentionally internal; records use `(emp_code, date)` as their natural key. Missing `history` and `half_day` in legacy records are explicitly allowed and are treated as `[]` and `false`. A weekday with no attendance document is not an `ABSENT` record.
